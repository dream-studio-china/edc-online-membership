    付款提取准备就绪¶

    支付来源已完全提取。 本文档记录了 已完成过渡主机工作和剩余的运行时切换步骤。

    已完成¶

    • 付款来源现在仅位于 apps/payment/src 下 App\Payment\*（30 个文件）。
    • apps/payment有自己的内核、Composer锁、composer.json (crud-platform/payment-app)、配置、PHPUnit冒烟测试、FrankenPHP图像和MySQL 8.4服务。
    • 单体通过crud-platform/payment-app Composer路径包临时加载Payment；根路由、Doctrine 映射、服务、PHPStan、Deptrac 和 Rector 都指向该包。
    • 付款基线迁移拥有 payment_invoice、payment_outbox_message 和 payment_payer_directory — 三个付款拥有的表，没有非付款表的外键。
    • 付款发票使用付款拥有的 payer_uuid 标量，而不是与身份 users 的 ORM 关联。 payment_payer_directory 在转换期间将旧数字身份 ID 映射到 UUID。
    • Payment的InvoiceService写入持久的发件箱行；转换主机的 app:payment:outbox:publish 通过根异步传输发布已付款/失败/取消/退款的 v1 合约。
    • 交易通过幂等 trade_consumed_event 收件箱消耗这些合约；同步OrderInvoiceListener暂时保留以供观察。
    • 钱包使用Core UUID-to-local-ID合约，微信通过UUID解析自己的用户关系。付款不再导入身份实体或存储库。
    • 钱包扣除持久性将付款引用存储为 invoice_id 和 invoice_no 标量。其实体和存储库不再导入付款发票实体。
    • 电子钱包支付和扣除服务现在仅接受电子钱包拥有的标量引用。支付拥有网关和调整提供商组合适配器；根 App\Bridge\PaymentWallet\WalletBalanceAdjustmentPort 将支付标量端口转换为钱包持久性。
    • 钱包现在在其旧版 user_id 关联旁边双重写入 owner_uuid。应用程序钱包过滤和所有者级别对账使用UUID；旧外键将一直保留，直到钱包基线和贸易集成准备就绪。
    • Trade 的传统钱包支付/退款路径使用中性的基于 UUID 的WalletTransferPortInterface；它不再导入钱包存储库或传输服务。
    • 根 Dockerfile 在 composer install 之前复制 apps/payment，并且根调度程序独立发布付款发件箱行。
    • 支付应用在独立模式下通过PayerDirectoryReferenceResolver解析自己的PayerReferenceResolverInterface；整体将其绑定到身份适配器。
    • 支付应用程序包含其自己的 invoice 工作流状态机。

    过渡安全¶

    现有的同步 OrderInvoiceListener 暂时保持启用状态。 它保留当前的 ​​API 行为，同时观察持久路径。贸易 Inbox 使异步副本可以安全地重播：它记录事件 ID 并 有效负载哈希，将相同的重试视为无操作，并拒绝事件 ID 与不同的有效负载重用。

    在观察到以下情况之前，请勿删除同步侦听器：

    1. 支付发件箱发布和贸易消费者处理对于一个健康的市场来说是健康的 生产期限有限。 2.付费、失败、取消、部分退款、全额退款路径都有 通过持久的道路锻炼。
    2. 已重播失败的运输行和任何进行中的事件。
    3. 由此产生的最终一致性行为被支付接受并且 订购 API 客户端。

    剩余提取工作¶

    1. 引入共享代理和架构版本化序列化程序所需的 独立的支付工作者和数据库。不要将支付流量路由至 payment-app 在此完成之前：其本地学说传输无法 将生命周期事件传递给 Trade。
    2. 禁用并移除持久化后的同步OrderInvoiceListener 路径已满足观察标准。
    3. 在公开受保护的支付路由之前添加网关发出的身份验证； 当前的独立安全提供程序故意充当占位符。
    4. 将支付 HTTP 流量、工作线程和调度程序移至网关影子后面 布线，然后移除整体式主机组件。
    5. 在生产中观察到owner_uuid后，删除钱包的遗留问题 身份User关联。然后为 Wallet 提供自己的基线、app 运行时和共享消息传递/身份验证依赖项，然后再从 过渡主机。
