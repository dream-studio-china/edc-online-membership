    测试¶

    1. 测试结构¶

    该平台使用 PHPUnit 12.5 进行两层测试：

    等级 地点 数据库 描述
    根集成 tests/ SQLite var/test.db 单体应用的跨模块集成测试（963 项测试）
    每个应用程序单位 apps/{name}/tests/ SQLite var/test.db 特定于服务的单元+集成测试

    所有测试套件都使用 SQLite 内存数据库。不需要 MySQL 或 Docker 用于本地测试。测试环境通过phpunit.xml配置 APP_ENV=test。

    每个套件测试什么¶

    常见 (apps/common/tests/)¶

    • 实体测试：类别、评论、内容、媒体、页面、图片、设置、标签
    • 媒体上传/删除控制器集成
    • 图片CRUD集成
    • 存储服务测试（LocalStorage、QiniuStorage）
    • 初始化QiniuSettingsCommand

    身份 (apps/identity/tests/)¶

    • 身份验证控制器（登录、注册、刷新、注销）
    • OTP 控制器（请求、验证）
    • TokenManager（JWT 创建、刷新轮换、重用检测）
    • UserService（注册、密码哈希、个人资料更新）
    • 微信模块（登录流程、WechatUser、认证服务）
    • 控制器集成测试

    贸易 (apps/trade/tests/)¶

    • 实体测试：产品、规格、订单、订单项
    • OrderService（创建、支付、退款、履行、计算价格）
    • 定价计算器（基本、数量、TotalAggregator、促销）
    • 推广 DSL：词法分析器、解析器、评估器、7 种策略
    • 促销计算器集成
    • 控制器集成（产品、订单、规格）
    • 消息处理程序测试（存储接受/拒绝消费者）

    钱包 (apps/wallet/tests/)¶

    • 实体测试：钱包、WalletTransaction
    • WalletService（创建、平衡、冻结）
    • TransferService（转账、充值等幂）
    • 支付集成（WalletPaymentDeduction、WalletGateway）
    • API回归测试
    • 异常测试（InsufficientFundsException等）

    付款 (apps/payment/tests/)¶

    • 网关测试（MockGateway、WalletGateway、WechatPayGateway）
    • PaymentGatewayRegistry（自动装配发现）
    • 调整提供商测试（WalletBalanceAdjustmentProvider）
    • 发票实体和服务测试

    商店 (apps/store/tests/)¶

    • 商店实体/服务测试
    • 贸易→商店→贸易整合流程
    • 商店库存集成（预订流程）
    • 消息处理程序测试

    库存 (apps/inventory/tests/)¶

    • 实体测试（材料、库存、配方、预订）
    • 服务测试（预订处理、菜谱解析）
    • 集成测试（预订请求流程）
    • 消息处理程序测试
    • API 测试（材料、配方、库存）

    3. 根集成测试 (tests/)¶

    963 项跨模块测试，涵盖：

    • 核心框架：BaseService、ExpressionDqlParser、FlatNormalizer、RestController

    • LocaleListener：语言检测和翻译

    4. 在本地运行测试¶

    PHP 版本¶

    推荐的本地 PHP 是 Homebrew PHP 8.5，位于： 

    /opt/homebrew/opt/php@8.5/bin/php

    默认系统 php 可能指向 PHP 7.4 (macOS)，这是不够的。

    根测试¶

    # All root tests
/opt/homebrew/opt/php@8.5/bin/php vendor/bin/phpunit

# Specific test file
/opt/homebrew/opt/php@8.5/bin/php vendor/bin/phpunit tests/Core/Controller/System/EntityControllerTest.php

# With coverage
XDEBUG_MODE=coverage /opt/homebrew/opt/php@8.5/bin/php vendor/bin/phpunit --coverage-html var/coverage

    每个应用程序测试¶

    # Example: Trade tests
cd apps/trade
/opt/homebrew/opt/php@8.5/bin/php vendor/bin/phpunit

# With coverage
XDEBUG_MODE=coverage /opt/homebrew/opt/php@8.5/bin/php vendor/bin/phpunit --coverage-clover ../../build/coverage/trade.xml

    Docker 测试¶

    # Root tests in Docker
docker compose exec app php vendor/bin/phpunit

# Per-app tests in Docker
docker compose exec trade-app php vendor/bin/phpunit

    烟雾脚本¶

    # API smoke test (requires running app)
bash scripts/tests/api-smoke.sh

# Store orchestration smoke (requires running Store + Trade)
bash scripts/tests/store-smoke.sh

# Trade workflow demo (generates 100 orders into SQLite)
/opt/homebrew/opt/php@8.5/bin/php scripts/tests/demo-trade-workflow.php

    6. 编写测试¶

    单元测试（服务层）¶

    位于每个应用程序的 tests/ 目录中。隔离测试业务逻辑：

    <?php

declare(strict_types=1);

namespace App\Wallet\Tests\Service;

use App\Wallet\Entity\Wallet;
use App\Wallet\Exception\InsufficientFundsException;
use App\Wallet\Service\WalletService;
use PHPUnit\Framework\TestCase;

final class WalletServiceTest extends TestCase
{
    private WalletService $walletService;
    private EntityManagerInterface $entityManager; // mocked

    protected function setUp(): void
    {
        $this->entityManager = $this->createMock(EntityManagerInterface::class);
        $this->walletService = new WalletService($this->entityManager);
    }

    public function testTransferFailsWhenInsufficientFunds(): void
    {
        $source = new Wallet(/* ... */, balance: 1000);  // cents
        $target = new Wallet(/* ... */, balance: 0);

        $this->expectException(InsufficientFundsException::class);
        $this->walletService->transfer($source, $target, 2000); // 2000 > 1000
    }
}

    集成测试（控制器/API 级别）¶

    位于每个应用程序的 tests/ 目录中。测试HTTP层：

    <?php

declare(strict_types=1);

namespace App\Trade\Tests\Integration;

use Symfony\Bundle\FrameworkBundle\Test\WebTestCase;

final class OrderControllerTest extends WebTestCase
{
    public function testCreateOrderReturns201(): void
    {
        $client = static::createClient();
        $client->request('POST', '/api/v1/app/orders', [
            'json' => [
                'items' => [
                    ['specificationId' => 'uuid-here', 'quantity' => 2],
                ],
            ],
        ]);

        $this->assertResponseStatusCodeSame(201);
        $data = json_decode($client->getResponse()->getContent(), true);
        $this->assertArrayHasKey('data', $data);
        $this->assertArrayHasKey('id', $data['data']);
    }
}

    根集成测试¶

    位于tests/Integration/。这些测试跨服务工作流程和核心 框架组件：

    <?php

declare(strict_types=1);

namespace App\Tests\Integration\Trade;

use Symfony\Bundle\FrameworkBundle\Test\WebTestCase;

final class OrderWorkflowTest extends WebTestCase
{
    public function testFullOrderLifecycle(): void
    {
        $client = static::createClient();
        // 1. Login
        // 2. Create order
        // 3. Pay order
        // 4. Fulfill order
        // 5. Verify wallet balance changes
    }
}

    赛程¶

    使用内联实体创建或数据提供程序：

    public static function orderAmountProvider(): array
{
    return [
        'small order' => [1000, 1],    // $10.00, 1 item
        'large order' => [100000, 5],  // $1000.00, 5 items
    ];
}

#[DataProvider('orderAmountProvider')]
public function testPaymentCalculation(int $amount, int $itemCount): void
{
    // ...
}

    嘲笑¶

    • createMock() 用于单元测试中的服务依赖关系
    • EntityManagerInterface 是最常被嘲笑的依赖项
    • 避免嘲笑实体；为值对象语义创建真实实例
    • 对于控制器测试，使用 WebTestCase::createClient() 启动完整的 Symfony 内核与 SQLite

    7. 测试命名约定¶

    • 测试类：{TargetClass}Test.php — 例如，OrderServiceTest.php
    • 测试方法：test{Scenario}()或test{Method}{Condition}()
    • testTransferFailsWhenInsufficientFunds()
    • testCreateOrderReturns201()
    • testInvoiceLifecycle()
    • 数据提供者：{context}Provider() 返回命名案例数组
    • 测试目录：镜像tests/下的源结构

    8. CI 测试作业¶

    每个应用程序测试套件作为单独的 GitHub Actions 作业并行运行：

    jobs:
  test-common:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: php-actions/composer@v6
      - run: cd apps/common && composer test -- --coverage-clover ../../build/coverage/common.xml

  test-identity:
    # ... similar for each app

    所有每个应用程序的覆盖工件都通过 phpcov 合并： 

    phpcov merge build/coverage --clover build/coverage/merged.xml

    合并门在 ≥ 90% 总线路覆盖率 时强制执行。
