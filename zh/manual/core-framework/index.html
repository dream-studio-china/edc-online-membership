    核心框架参考¶

    深入研究packages/platform-kernel/src/。这是基础共享库——它 不得依赖于任何业务模块。

    1.RestController¶

    文件：packages/platform-kernel/src/Controller/RestController.php 扩展：Symfony\Bundle\FrameworkBundle\Controller\AbstractController

    平台中的每个控制器都扩展RestController。它提供 JSON 响应助手， 分页、请求处理、服务解析和 setter 注入的依赖项。

    1.1 构造函数和 Setter 注入¶

    构造函数接受可选的依赖项。 #[Required]设置者保证生产 注入，同时允许子类省略显式 parent::__construct() 调用。

    class RestController extends AbstractController
{
    private ?RequestStack $requestStack = null;
    private ?SerializerInterface $serializer = null;
    private ?TranslatorInterface $translator = null;
    private ?ContainerInterface $serviceContainer = null;

    public function __construct(
        ?RequestStack $requestStack = null,
        ?SerializerInterface $serializer = null,
        ?TranslatorInterface $translator = null
    ) { /* ... */ }

    #[Required] public function setRequestStack(RequestStack $requestStack): void { /* ... */ }
    #[Required] public function setSerializer(SerializerInterface $serializer): void { /* ... */ }
    #[Required] public function setTranslator(TranslatorInterface $translator): void { /* ... */ }
    #[Required] public function setServiceContainer(ContainerInterface $serviceContainer): void { /* ... */ }
}

    所有四个 #[Required] 设置器：

    二传手 依赖 目的
    setRequestStack() RequestStack 访问当前请求，查询参数
    setSerializer() SerializerInterface 响应的 JSON 序列化
    setTranslator() TranslatorInterface 区域设置感知消息翻译
    setServiceContainer() ContainerInterface 惰性服务解析 (resolveService())

    1.2 成功()¶

    protected function success(
    mixed $content = '',
    string $addition_message = 'SUCCESS',
    int $status = 200
): Response

    成功路径贯穿：pagination(content)→requestProcess(items)→序列化并返回。

    JSON 信封：

    {
    "data": [],
    "code": 0,
    "message": "SUCCESS"
}

    分页时（使用 page/limit 的 GET 请求），将添加 paginator 键：

    {
    "data": [],
    "code": 0,
    "message": "SUCCESS",
    "paginator": {
        "total": 42,
        "page": 1,
        "limit": 100,
        "pages": 1,
        "has_previous": false,
        "has_next": false
    }
}

    如果status === 204，则返回空响应（由DeleteApiViewMixin使用）。

    1.3 警告()¶

    protected function warning(
    string $error_msg = self::UNKNOWN_ERROR,
    int $error_code = -1,
    mixed $raw_data = '',
    int $status = 200
): Response

    返回错误信封。消息经过getTranslator()->trans()：

    {
    "code": 404,
    "message": "Entity is not found",
    "raw_data": ""
}

    默认状态为 200，因此客户端会看到 HTTP 200 和应用程序级错误 代码。控制器可以覆盖$status（例如，400、404、500）。

    1.4 分页()¶

    接受 QueryBuilder、array 或 ArrayCollection。对于查询构建器，使用 DoctrinePaginator 在设置setFirstResult()/setMaxResults()之前计算$total。 对于数组/集合，使用 array_slice()。

    默认页面限制为 100。分页器元数据：total、page、limit、pages、 has_previous、has_next。

    1.5 @expands 处理¶

    requestProcess() 方法从 查询字符串。对于每个点路径，它遍历 getter 并在相关的上注入 __metadata 对象，以便序列化器可以包含嵌套数据。

    1.6 @display 处理¶

    同样在 requestProcess() 中：

    价值 行为
    complex（默认） 按原样返回集合（序列化程序处理它）
    reduce 将每个实体映射到 {id, __toString}
    ["name", "slug"]（JSON 数组） 从每个实体中提取命名字段
    {"name": "entity.getName()", "count": "Math.sqrt(16)"}（JSON 对象） 评估范围内具有 entity、Math、ArrayCommon 的每个实体的表达式

    1.7 getService()/resolveService()¶

    • getService()：通过反射读取$this->service属性，如果不是对象则抛出异常。
    • resolveService(string $id)：从$this->serviceContainer获取，如果不可用则抛出。 由TransformContent用来解析相关实体服务。

    2. 基础服务和特征¶

    文件：packages/platform-kernel/src/Service/BaseService.php 实现：BaseServiceInterface 模板：@template TEntity of object

    2.1 基础服务构造函数¶

    public function __construct(
    ContainerInterface $container,
    string $entityClass,                         // e.g., Category::class
    ?ServiceLocatorInterface $locator = null,
    ?ExpressionServiceInterface $expressionService = null,
    ?LegacyEvaluator $legacyEvaluator = null
)

    关于施工： 1. 通过ServiceLocatorInterface解析EntityManager和存储库 2.从TokenStorage设置$this->user（未经身份验证的请求为空） 3. 存储可选的 ExpressionService / LegacyEvaluator 引用

    属性： - $container — Symfony DI 容器 - $em — EntityManager - $rep — $entityClass 的学说存储库 - $entityClass — 受管实体 FQCN - $logger — PSR 记录器 - $user — 当前经过身份验证的用户或 null

    2.2 基础服务基础设施特征¶

    文件：packages/platform-kernel/src/Service/Concern/BaseServiceInfrastructureTrait.php

    方法 描述
    wrapInTransaction(callable $fn) 开始 Tx → 执行 → 刷新 → 提交。在\Throwable上：回滚+重新抛出。如果 EM 缺乏交易方法（测试假货），则退回到普通执行。
    getEntityManager() 来自 $this->em 或 $this->container 的惰性解析
    getRepository(?string $class) 返回 EntityManager::getRepository($class)
    getLogger() 惰性解析，如果不可用则返回 NullLogger
    getSerializer() 从 ServiceLocator 开始惰性解析，然后是 $this->container，然后创建一个普通的 ObjectNormalizer+JsonEncoder
    getValidator() 返回 Symfony 验证器（如果可用）
    getRequestStack() / getCurrentRequest() 访问当前HTTP请求
    getQueryBuilderFactory() 按需创建 QueryBuilderFactory
    getExpressionService() 按需创建 ExpressionService
    getLegacyEvaluator() 按需创建 LegacyEvaluator
    externalExpressionValues() 返回 ['math' => Math, 'datetime' => FilterDateTime, 'Math' => Math, 'Datetime' => FilterDateTime, 'ArrayCommon' => ArrayCommon]
    listResultToCollection() 将 QueryBuilder 或 array 转换为 ArrayCollection

    2.3 BaseServiceReadListTrait¶

    文件：packages/platform-kernel/src/Service/Concern/BaseServiceReadListTrait.php

    获取（）¶

    public function get(mixed $object, bool $directly = false)

    解析逻辑： 

    - null                     → null
- QueryBuilder             → getSingleResult()
- object with getId()      → $this->rep->find($entityId)
- array<string, mixed>     → $this->rep->findOneBy($array)
- string (valid UUID)      → $this->rep->findOneBy(['uuid' => $string]) if entity has UUID field
- int|string (fallback)    → $this->rep->find($object)

    列表（）¶

    public function list(mixed $object = null, mixed $order = null, bool $disableRequest = true): mixed

    当$disableRequest为false时，该方法处理来自 当前请求：

    • @filter：通过子句中的ExpressionService::buildFilter()→DQL子查询→EXISTS进行解析。 解析失败时：如果是 admin，则回退到内存中过滤 + usort；如果非管理员，则抛出 AccessDeniedHttpException。
    • @dql：原始 DQL 作为 IN 子查询注入。仅限管理员（由 assertPrivilegedQueryParameters()）。
    • @order：语法field|ASC, field2|DESC。将点路径转换为连接别名 自动。
    • @select：DQL SELECT 投影。如果触及 user|profile|password|roles|email|phone|phoneVerified|refreshToken|sessionKey|rawData 则被阻止 或目标 App\Identity\* 实体。
    • @groupBy：DQL GROUP BY 子句。
    • @hints：JSON 解码的 Doctrine 查询提示。仅限管理员。
    • @sort：基于表达式的usort()，带有x和y对象。触发回退到 内存模式。仅限管理员。
    • @showDQL：仅限开发。抛出包含已编译 DQL 的 ValidatorException。

    安全选择防护：assertSafeSelect() 阻止访问身份字段的投影 （参见$identityFields正则表达式）。任何针对 App\Identity\* 实体的 @select 都会被拒绝。

    特权参数保护：assertPrivilegedQueryParameters() 限制 @dql、@sort、 @hints 至 ROLE_ADMIN。 @showDQL 需要 dev 环境。

    2.4 基础服务突变特征¶

    文件：packages/platform-kernel/src/Service/Concern/BaseServiceMutationTrait.php

    新的（）¶

    创建 $this->entityClass 的新实例。如果构造函数没有必需的参数， 使用newInstance()。否则，使用 newInstanceWithoutConstructor()。

    更新（）¶

    管道：

    1. Validate object not null
2. Re-fetch from DB if entity has an ID (prevents detached-entity issues)
3. For each key in $data:
   a. Check property exists
   b. If #[ManyToOne]/#[OneToOne]: resolve target entity, call setter, unset from $data
   c. If #[ManyToMany]/#[OneToMany]: diff current vs new IDs, call add*/remove* (using Inflect::singularize), unset
   d. If date-like mapping (ORM type datetime/date/time or property type \DateTimeInterface): create DateTime, call setter, unset
4. Deserialize remaining $data onto the object (using Serializer with object_to_populate)
5. Validate the entity (Symfony Validator)
6. Persist + flush
7. Return the entity (or false on reflection error)

    关系处理：ManyToOne/OneToOne 通过存储库查找设置另一个实体。 ManyToMany/OneToMany 计算差异（添加的 ID 与删除的 ID）并调用加法器/删除器。

    日期时间转换：通过 ORM 属性 type 或属性 PHP 类型检测 \DateTimeInterface。将标量值转换为 new \DateTime($val)。

    remove()：调用 get() 进行解析，然后调用 $em->remove() + $em->flush()。返回布尔值。

    3. 查看混入¶

    所有 mixin 都位于 packages/platform-kernel/src/View/ 中。他们通过以下方式组成控制器 trait 用法而不是深层类层次结构。

    3.1 ApiView（强制基本特征）¶

    特质：App\Core\View\ApiView

    每个控制器必须 use ApiView。它提供：

    属性/方法 目的
    $serviceClass 对应服务的FQCN
    commonFilter() 覆盖以应用所有权/范围过滤器。返回 array 或 QueryBuilder
    mixIdToCommonFilter($id) 将 ['id' => $id] （或 ['uuid' => $id]）添加到 commonFilter
    mixToCommonFilter($data) 将 $data 合并到 commonFilter 结果
    entityNotFoundMessage() 返回“找不到实体”（可以覆盖）

    commonFilter() 范围模式： 

    // User-scoped: only user's own data
protected function commonFilter(): array { return ['ownerUuid' => $this->getUser()->getUuid()]; }

// Admin: no filter (everything visible)
protected function commonFilter(): array { return []; }

// Block-all: prevents access (used when controller should only expose custom actions)
protected function commonFilter(): array { return ['id' => -1]; }

// Public: filter for published/enabled items
protected function commonFilter(): array { return ['enabled' => true]; }

    3.2 ListApiViewMixin¶

    路线：GET /→listAction()

    钩 当被呼叫时 目的
    listFilter($filter) service.list()之前 修改过滤条件
    listProcessor($entities) service.list() 之后 转换结果集
    listResponses($entities) 连载前 最终反应塑造

    记录的 OpenAPI 参数：page、limit、@order、@dql、@select、@groupBy、 @hints、@filter、@sort、@expands、@display、@showDQL。

    3.3 DetailApiViewMixin¶

    路由：GET /{id}（支持\d+和UUID [0-9a-fA-F-]{36}）

    钩 当被呼叫时 目的
    detailFilter($filter) mixIdToCommonFilter 之后，get() 之前 修改查找条件
    detailProcessor($entity) service.get() 之后 变换实体
    detailResponse($entity) 连载前 响应塑造

    3.4 CreateApiViewMixin¶

    路线：POST /→createAction()

    物业 类型 目的
    $requiredCreateProperties string[] 必须存在的字段
    $acceptedCreateProperties string[] 可能存在的字段

    查询参数：@partial（跳过事务）、@transform（表达式转换器）。

    输入模式： - {} (object): 单一创建，直接返回实体 - [{}, {}]（数组）：批量创建，包装在事务中（除非@partial=true）

    钩 当被呼叫时
    defaultCreateValues() 加工前
    processCreateContent(array $content, $entity) 变换后、保存前
    processEntity($content, $entity) new() 之后，update() 之前
    afterCreated($entity) 保存成功后

    3.5 更新ApiViewMixin¶

    路线： - PUT /{id} → updateAction() - POST /batch-update → batchUpdateAction()

    查询参数：@mode=mixed|strict、@basis=field1,field2、@partial、@transform。

    使用 @mode=mixed 进行批量更新插入：尝试通过 @basis 字段查找实体。如果发现→ 更新；如果没有找到→创建。

    钩 当被呼叫时
    defaultUpdateValues() 加工前
    processUpdateContent(array $content, $entity) 变换后、保存前
    afterUpdated($entity) 保存成功后

    兼容性挂钩（默认更新路径，覆盖不同行为）： - defaultValues() → defaultUpdateValues() - processContent($content, $entity) → processUpdateContent() - after($entity) → afterUpdated()

    3.6 删除ApiViewMixin¶

    路线：DELETE /{id}→deleteAction()

    钩 当被呼叫时
    deletionFilter($filter) 查找前

    成功则返回 204（空主体），失败则返回 404。

    3.7 WorkflowApiViewMixin¶

    对于由 Symfony Workflow 状态机管理的实体。 需要 protected $workflow; 设置为工作流服务 ID。

    路线 行动
    GET /todo 列出具有可用转换的实体
    GET /{id}/transitions 获取实体的启用转换
    POST /{id}/do/{transition} 执行工作流程转换（包含在 wrapInTransaction 中）
    PUT /{id}/status-reset 重置标记（仅限 ROLE_ADMIN）

    3.8 SingleCreateAndUpdateApiViewMixin¶

    路线：PUT /→updateAction()

    对于每个范围只有一行的资源（例如，用户设置）。如果该实体存在 （通过commonFilter），它更新。如果没有，它就会创造。

    声明 $requiredCreateProperties / $acceptedCreateProperties 和 $requiredUpdateProperties / $acceptedUpdateProperties，每个通过单独过滤 filterCreateProperties() / filterUpdateProperties()。

    3.9 ScopedDetailApiViewMixin¶

    路线：GET /{id}

    抽象混合。控制器必须实现：

    abstract protected function scopedDetailFilter(string $scopeId, string $id): array|QueryBuilder;

    $scopeId 来自 URL 前缀（例如 /{productId}/specifications/{id}）。

    3.10 ScopedListApiViewMixin¶

    路线：GET /

    抽象混合。控制器必须实现：

    abstract protected function scopedListFilter(string $scopeId): array|QueryBuilder;

    3.11 SingleDetailApiViewMixin¶

    路线：GET /

    通过 commonFilter() 获取单个资源（URL 中没有 ID）。

    3.12 变换内容¶

    特质：App\Core\View\TransformContent
    使用者：ApiView

    在保存之前评估 @transform 表达式以解析字段值。示例：

    POST /api/contents with data: {"title": "Hello", "category": "Test"}
@transform: {"category": "Service.get({'name': ':value'}).getId()"}
    • :value 替换为请求正文中的原始字段值
    • Service为相关实体的服务提供.get($criteria)和.list($criteria)网关
    • Service.get() 返回带有 .getId() 的身份包装器 → 解析外键
    • entity 是使用 .getId() 封装在身份网关中的当前实体
    • Math 和 ArrayCommon 可用作表达式变量

    变压器通过将中的Entity替换为Service来检测相关服务FQCN 目标实体的命名空间，然后调用 resolveService()。

    3.13 ApiViewMessages¶

    文件：platform-kernel/src/View/ApiViewMessages.php

    所有 mixin 使用的集中消息常量：

    常数/方法 价值观/行为
    SUCCESS 'SUCCESS'
    ENTITY_NOT_FOUND 'Entity is not found'
    INVALID_JSON 'Invalid JSON'
    CREATE_FAILED 'Create failed'
    BATCH_UPDATE_ERROR 'Batch update error'
    CONTENT_TYPE_ERROR 'Content type error.'
    TRANSITION_CANNOT_APPLY 'Current transition cannot be applied.'
    propertyRequired($prop) 'Ucfirst($prop) is required'
    propertyCannotBeEmpty($prop) 'Ucfirst($prop) cannot be empty.'

    4. 事件监听器¶

    4.1 异常拦截器¶

    文件：packages/platform-kernel/src/EventListener/ExceptionInterceptor.php 事件：kernel.exception

    拦截 /api/* 路由上的异常（正则表达式：/^\/(api)\/.*$/）。

    行为： - 记录异常（消息+类） - 在 dev.disabled env 中：让 Symfony 的默认错误处理程序处理它 - 在生产中：返回 JSON {code: statusCode, message: translated(message), class: FQCN} - 状态代码：使用 HttpExceptionInterface::getStatusCode()（如果可用），然后回退 到 $exception->getCode() 如果 400-599，则 500

    {
    "code": 500,
    "message": "Api error occurred",
    "class": "RuntimeException"
}

    4.2 控制器监听器¶

    文件：packages/platform-kernel/src/EventListener/ControllerListener.php 事件：kernel.controller

    文件：packages/platform-kernel/src/EventListener/LocaleListener.php 事件：kernel.request

    ja-JP、ja_JP ja

    4.4 访问日志监听器¶

    文件：packages/platform-kernel/src/EventListener/AccessLogListener.php 事件：kernel.response

    将 POST、PUT、DELETE 方法的完整请求/响应正文记录到 access 日志通道 (monolog.logger.access)。

    • 身份验证路径（/api/auth、/api/wechat）隐藏了主体
    • 非身份验证路径：正文被截断为 4096 个字符

    4.5 OpenApiEnricherListener¶

    文件：packages/platform-kernel/src/EventListener/OpenApiEnricherListener.php 事件：kernel.response

    后处理 /api/doc.json 和 /api/doc 响应：

    • 通过解析 operationId 注入特定于模块的标签（产品、订单、类别等） 来自路线名称（例如 manage-categories-list → Categories）
    • 删除通用操作类型标签（List、Detail、Create、Update、Delete、 Workflow) 来自 View mixin OA 属性
    • 添加重要端点的 META 常量的摘要/描述
    • 为媒体上传端点注入 multipart/form-data 请求主体架构

    标签检测逻辑： 

    operationId → parse {scope}-{resource}-{action}
  → map known resources (product→Products, order→Orders, etc.)
  → auto-title-case for unknown resources

    5. 序列化器¶

    5.1 平坦标准化器¶

    文件：packages/platform-kernel/src/Serializer/Normalizer/FlatNormalizer.php 实现：NormalizerInterface、DenormalizerInterface、NormalizerAwareInterface、 SerializerAwareInterface

    装饰 Symfony 的 ObjectNormalizer。关键转变：

    1. Doctrine internals → __toString() if available, else class name
    2. __toString added to every serialized entity at top level
    3. Related entities (objects with getId()) → collapsed to {id, __toString, __metadata}
    4. Collections (Traversable) → array of reduced relation objects
    5. JSON strings in fields → auto-parsed to arrays/objects
    6. Falls back to minimal representation on normalization failure: {id, __toString} or {__class: FQCN}

    Denormalization: Delegates to decorated normalizer.
