    部署¶

    1. Docker Compose 拓扑¶

    该平台使用 Docker Compose 和 22 项服务：

    ＃ 服务 图片 目的
    1 app 弗兰肯PHP 8.4 根整体（API + HTTP）
    2 worker 弗兰肯PHP 8.4 Messenger 异步使用者（仅限 CLI）
    3 scheduler 弗兰肯PHP 8.4 发件箱中继（贸易、商店、库存、付款）
    4 store-app 弗兰肯PHP 8.4 商店申请
    5 inventory-app 弗兰肯PHP 8.4 库存申请
    6 payment-app 弗兰肯PHP 8.4 支付申请
    7 wallet-app 弗兰肯PHP 8.4 钱包应用
    8 identity-app 弗兰肯PHP 8.4 身份申请
    9 common-app 弗兰肯PHP 8.4 常见应用
    10 10 trade-app 弗兰肯PHP 8.4 贸易申请
    11 11 database MySQL 8.4 MySQL 8.4根整体数据库
    12 12 store-database MySQL 8.4 MySQL 8.4存储数据库
    13 inventory-database MySQL 8.4 MySQL 8.4库存数据库
    14 14 payment-database MySQL 8.4 MySQL 8.4支付数据库
    15 15 wallet-database MySQL 8.4 MySQL 8.4钱包数据库
    16 16 identity-database MySQL 8.4 MySQL 8.4身份数据库
    17 17 common-database MySQL 8.4 MySQL 8.4通用数据库
    18 18 trade-database MySQL 8.4 MySQL 8.4贸易数据库
    19 19 redis Redis 7 高山 OTP 存储
    20 mailer 邮件坑 电子邮件测试（SMTP + Web UI）
    — database-test MySQL 8.4 MySQL 8.4 （仅限 compose.override.yaml）

    基础设施服务¶

    服务 内部端口 主机端口 笔记

    Worker 和调度程序覆盖 APP_ENV=prod 并禁用继承的 HTTP 端口 和健康检查（它们是 CLI 服务）。

    3. 开发与生产叠加¶

    开发（compose.override.yaml — 自动加载）¶

    services:
  app:
    environment:
      APP_ENV: dev
      APP_DEBUG: "1"
    volumes:
      - .:/var/www/html  # Source mount for live reload
    ports:
      - "8080:80"

  store-app:
    environment:
      APP_ENV: dev
      APP_DEBUG: "1"
    volumes:
      - ./apps/store:/var/www/html
    • 源代码直接安装到容器中
    • APP_DEBUG已启用
    • 自动生成 Dev JWT 密钥 (docker/app/entrypoint.sh)
    • 为 Symfony Runtime 创建的空 .env 占位符

    生产 (compose.prod.yaml)¶

    docker compose -f compose.yaml -f compose.prod.yaml --env-file .env.prod.local up -d --build

    生产要求： - .env.prod.local 基于.env.prod.example - 必须设置：APP_SECRET、REFRESH_TOKEN_SECRET、MYSQL_PASSWORD、MYSQL_ROOT_PASSWORD - 每个应用程序都需要自己的秘密（例如，STORE_APP_SECRET、STORE_MYSQL_PASSWORD） - 在 ./var/jwt/ 主机上生成的 JWT 密钥，安装到容器中 - APP_DEBUG=0，没有源安装 - 所有服务上的 restart: unless-stopped

    4.环境变量参考¶

    Symfony 核心¶

    变量 必填 默认 描述
    APP_ENV 是的 prod dev、test 或 prod
    APP_DEBUG 没有 0 调试模式（0 或 1）
    APP_SECRET 是 — Symfony 应用程序秘密（产品）
    DATABASE_URL 是的 — MySQL DSN

    JWT 身份验证¶

    变量 必填 默认 描述
    JWT_PRIVATE_KEY_PATH 是的 /var/www/html/var/jwt/jwt_private.pem RSA 私钥路径
    JWT_PUBLIC_KEY_PATH 是的 /var/www/html/var/jwt/jwt_public.pem RSA 公钥的路径
    JWT_PASSPHRASE 没有 — 私钥密码
    ACCESS_TOKEN_TTL 没有 7200 访问令牌生命周期（秒）
    REFRESH_TOKEN_TTL 没有 31536000 刷新令牌生命周期（1 年）
    REFRESH_TOKEN_SECRET 是 — HMAC-SHA256 秘密（产品，≥32 个字符）

    一次性密码/短信¶

    变量 必填 默认 描述
    OTP_REDIS_DSN 没有 redis://redis:6379/0 用于 OTP 存储的 Redis
    ALIYUN_ACCESS_KEY_ID 没有 — 阿里云短信
    ALIYUN_ACCESS_KEY_SECRET 没有 — 阿里云短信
    ALIYUN_SMS_REGION 没有 cn-hangzhou 短信区域
    ALIYUN_SMS_SIGN_NAME 没有 — 短信签名
    ALIYUN_SMS_TEMPLATE_LOGIN_OTP 没有 — 登录一次性密码模板
    ALIYUN_SMS_DRY_RUN 没有 true 禁用实际短信发送

    微信¶

    变量 必填 描述
    WECHAT_MINIAPP_APP_ID 没有 小程序App ID
    WECHAT_MINIAPP_SECRET 没有 小程序揭秘
    WECHAT_OFFICIAL_APP_ID 没有 公众号App ID
    WECHAT_OFFICIAL_SECRET 没有 公众号揭秘
    WECHAT_PAY_MCH_ID 没有 微信支付商户ID
    WECHAT_PAY_SECRET_KEY 没有 微信支付 APIv3 密钥
    WECHAT_PAY_PRIVATE_KEY 没有 商户私钥路径
    WECHAT_PAY_CERTIFICATE 没有 平台证书路径
    WECHAT_PAY_NOTIFY_URL 没有 付款通知回调网址

    基础设施¶

    变量 必填 默认 描述
    MAILER_DSN 没有 smtp://mailer:1025 邮寄运输
    MESSENGER_TRANSPORT_DSN 没有 doctrine://default?auto_setup=0 异步传输
    DEFAULT_URI 没有 http://localhost 基本网址
    INVENTORY_ENABLED 没有 0 全球库存切换
    OUTBOX_PUBLISH_INTERVAL 没有 5 发件箱中继间隔（秒）

    每个应用程序变量¶

    每个应用程序都使用带前缀的环境变量：

    应用程序 前缀 示例
    商店 STORE_ STORE_APP_SECRET、STORE_DATABASE_URL、STORE_MYSQL_PASSWORD
    库存 INVENTORY_ INVENTORY_APP_SECRET、INVENTORY_DATABASE_URL
    付款 PAYMENT_ PAYMENT_APP_SECRET、PAYMENT_DATABASE_URL
    钱包 WALLET_ WALLET_APP_SECRET、WALLET_DATABASE_URL
    身份 IDENTITY_ IDENTITY_APP_SECRET、IDENTITY_DATABASE_URL
    常见 COMMON_ COMMON_APP_SECRET、COMMON_DATABASE_URL
    贸易 TRADE_ TRADE_APP_SECRET、TRADE_DATABASE_URL

    5. Docker 中的 JWT 密钥管理¶

    发展¶

    开发入口点 (docker/app/entrypoint.sh) 自动生成密钥：

    if [ ! -f /var/www/html/var/jwt/jwt_private.pem ]; then
    mkdir -p /var/www/html/var/jwt
    openssl genpkey -algorithm RSA -out /var/www/html/var/jwt/jwt_private.pem \
      -pkeyopt rsa_keygen_bits:4096
    openssl rsa -pubout -in /var/www/html/var/jwt/jwt_private.pem \
      -out /var/www/html/var/jwt/jwt_public.pem
fi

    密钥在挂载的 ./var/jwt 目录下生成一次并保留 跨容器重新启动。

    生产¶

    密钥在 主机 机器上生成并安装：

    # On host
mkdir -p var/jwt
openssl genpkey -algorithm RSA -out var/jwt/jwt_private.pem \
  -pkeyopt rsa_keygen_bits:4096 -aes256 -pass pass:${JWT_PASSPHRASE}
openssl rsa -pubout -in var/jwt/jwt_private.pem \
  -out var/jwt/jwt_public.pem -passin pass:${JWT_PASSPHRASE}
chmod 600 var/jwt/jwt_private.pem
chmod 644 var/jwt/jwt_public.pem

    生产入口点验证 JWT 密钥是否存在并退出并出现错误 如果钥匙丢失。

    6. 构建图像¶

    根巨石¶

    docker compose build app

    使用根Dockerfile（FrankenPHP 8.4 Alpine，Caddyfile位于docker/frankenphp/Caddyfile）。

    每应用程序服务¶

    每个应用程序都有自己的 Dockerfile 和 docker/Caddyfile：

    docker compose build store-app
docker compose build payment-app
# ... etc

    Dockerfile 位于 apps/{name}/Dockerfile 中。构建上下文是存储库 整体应用程序的根目录，以及每个应用程序服务的单独应用程序目录。

    构建全部¶

    docker compose build

    7. 在生产中运行迁移¶

    # Root monolith
docker compose exec app php bin/console doctrine:migrations:migrate --no-interaction

# Each app
docker compose exec store-app php bin/console doctrine:migrations:migrate --no-interaction
docker compose exec inventory-app php bin/console doctrine:migrations:migrate --no-interaction
docker compose exec payment-app php bin/console doctrine:migrations:migrate --no-interaction
docker compose exec wallet-app php bin/console doctrine:migrations:migrate --no-interaction
docker compose exec identity-app php bin/console doctrine:migrations:migrate --no-interaction
docker compose exec common-app php bin/console doctrine:migrations:migrate --no-interaction
docker compose exec trade-app php bin/console doctrine:migrations:migrate --no-interaction

    重要：首先运行根整体迁移，然后运行每个应用程序迁移。 每个迁移链都是独立的。

    创建管理员用户¶

    docker compose exec app php bin/console app:identity:user:create admin@example.com admin 'P@ssw0rd' --admin

    8. 用于电子邮件测试的 Mailpit¶

    Mailpit 捕获所有外发电子邮件：

    • SMTP 端点：mailer:1025（内部）、localhost:1025（主机）
    • 网络用户界面：http://localhost:8025
    • 所有电子邮件均被拦截并可在用户界面中查看
    • 不会将电子邮件发送给真正的收件人

    在.env中配置： 

    MAILER_DSN=smtp://mailer:1025

    9. 用于 OTP 的 Redis¶

    Redis 使用 TTL 存储 OTP 代码。无需持久存储。

    • 连接：redis://redis:6379/0
    • 数据库索引：0
    • OTP 代码自动过期（可配置 TTL）

    10.FrankenPHP / Caddyfile 配置¶

    根整体 Caddyfile (docker/frankenphp/Caddyfile)¶

    {
    frankenphp
}

:80 {
    header {
        Access-Control-Allow-Origin *
        Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS"
        Access-Control-Allow-Headers "Content-Type, Authorization"
    }

    root * /var/www/html/public/
    php_server {
        resolve_root_symlink
    }
    encode gzip
    file_server
}

    每个应用程序 Caddyfiles (apps/{name}/docker/Caddyfile)¶

    每个应用程序都有一个为其自己的 public/ 目录配置的类似 Caddyfile 和内部端口 80。

    11. compose.prod.yaml 用法¶

    # 1. Create env file from example
cp .env.prod.example .env.prod.local
# Edit with real secrets

# 2. Generate JWT keys on host
# (see section 5)

# 3. Start production stack
docker compose -f compose.yaml -f compose.prod.yaml --env-file .env.prod.local up -d --build

# 4. Run migrations
docker compose exec app php bin/console doctrine:migrations:migrate --no-interaction
# ... repeat for each app

# 5. Create admin user
docker compose exec app php bin/console app:identity:user:create admin@example.com admin 'P@ssw0rd' --admin

    生产与开发的差异¶

    特色 开发 产品
    源安装 是的 没有
    APP_DEBUG 1 0
    JWT 密钥 自动生成 主机生成+挂载
    秘密 compose.yaml 中的默认值 .env.prod.local
    港口 直接暴露 通过反向代理（推荐）
    记录 标准错误 文件或收集器
    健康检查 在工作程序/调度程序上禁用 必填
