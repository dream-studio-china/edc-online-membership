    提取服务¶

    本指南涵盖了从其中提取业务模块的端到端过程 将根整体集成到 apps/ 下其自己的独立可启动服务中。

    提取前检查清单¶

    在提取之前，模块必须满足这些边界规则 Microservice Transition Contract：

    • [ ] 无跨军种学说关联 — 删除所有 FK 关系 其他服务中的实体。替换为 UUID 引用。
    • [ ] 无跨服务存储库访问 — 该模块不会注入或 从其他服务调用存储库。
    • [ ] 无跨服务事务 — 模块的数据库操作 是完全独立的。
    • [ ] UUID 身份 — 外部引用使用 UUID，而不是本地整数 PK。
    • [ ] 跨服务写入的发件箱 — 状态更改集成事件 被写入生产者本地事务中的发件箱。
    • [ ] 标量合约 — 无 Doctrine 实体、存储库或 Symfony 请求/响应跨越服务边界。
    • [ ] 没有共享的教义关联 — Identity\Entity\User 不是 模块实体映射中的 ORM 目标。
    • [ ] 存在测试 — 该模块有自己的测试套件，并且具有合理的测试套件 提取前的覆盖范围。

    已知的边界风险¶

    风险 描述 提取前的分辨率
    共享 User 实体 其他模块有ManyToOne → User 替换为 ownerUuid VARCHAR(36) （如钱包所做的那样）
    同步跨服务调用 贸易直接致电库存/付款 替换为发件箱/收件箱集成事件
    PHP 级 Messenger 合约 旧版 App\*\Message 包装器 迁移到 packages/integration-contracts/ 中的中立运营商
    暴露 Dotrine 类型的插件合约 支付/微信网关 创建标量适配器接口
    共享实体管理器 单一学说联系 配置独立数据库+EM

    步骤 1：创建 apps/{name}/ 骨架¶

    创建目录结构：

    mkdir -p apps/{name}/{bin,config/packages,docker,migrations,public,src,tests}

    所需文件¶

    apps/{name}/composer.json¶

    {
    "name": "crud-platform/{name}-app",
    "type": "project",
    "require": {
        "php": ">=8.4",
        "crud-platform/platform-kernel": "@dev",
        "symfony/framework-bundle": "^8.1",
        "doctrine/doctrine-bundle": "^3.0",
        "doctrine/doctrine-migrations-bundle": "^3.0",
        "doctrine/orm": "^3.6"
    },
    "autoload": {
        "psr-4": {
            "App\\{Module}\\": "src/"
        }
    },
    "autoload-dev": {
        "psr-4": {
            "App\\{Module}\\Tests\\": "tests/"
        }
    }
}

    重要：使用 @dev 作为平台内核。这确保了 monorepo 工作区解析本地包。

    apps/{name}/src/Kernel.php¶

    <?php

declare(strict_types=1);

namespace App\{Module};

use Symfony\Bundle\FrameworkBundle\Kernel\MicroKernelTrait;
use Symfony\Component\HttpKernel\Kernel as BaseKernel;

final class Kernel extends BaseKernel
{
    use MicroKernelTrait;
}

    apps/{name}/bin/console¶

    #!/usr/bin/env php
<?php

declare(strict_types=1);

use App\{Module}\Kernel;
use Symfony\Bundle\FrameworkBundle\Console\Application;

require_once dirname(__DIR__) . '/vendor/autoload_runtime.php';

return function (array $context) {
    $kernel = new Kernel($context['APP_ENV'], (bool) $context['APP_DEBUG']);
    return new Application($kernel);
};

declare(strict_types=1);

    // Security bundle only if the app needs auth
    // Symfony\Bundle\SecurityBundle\SecurityBundle::class => ['all' => true],

    安装依赖项¶

    cd apps/{name}
composer install

    验证启动： 

    php bin/console about

    步骤 2：移动源代码¶

    将源文件从根 src/{Module}/ 移动到 apps/{name}/src/。

    # Example: Moving Store
git mv src/Store/ apps/store/src/

    保留命名空间。命名空间变为 App\{Module}\* 而不是 App\{Module}\*。更新移动文件中的所有 namespace 声明。

    如果需要的话，取消实体前缀。例如，Store 实体被取消前缀： - StoreMembership → Membership（表名通过#[ORM\Table]保留为store_membership） - StoreOutboxMessage → OutboxMessage（表名保留为store_outbox_message） - StoreConsumedEvent → InboxMessage

    步骤 3：创建独立迁移基线¶

    创建单个迁移来捕获拥有的所有表的当前架构 通过服务。这是“基线”迁移——它代表了架构 提取点。

    cd apps/{name}
php bin/console doctrine:migrations:generate

    编辑生成的迁移以包含所有的 CREATE TABLE 语句 服务拥有的表。此迁移必须是幂等安全的（使用 CREATE TABLE IF NOT EXISTS）。

    示例（存储基线）¶

    final class Version20260730000000 extends AbstractMigration
{
    public function up(Schema $schema): void
    {
        $this->addSql('CREATE TABLE store (/* ... */)');
        $this->addSql('CREATE TABLE store_membership (/* ... */)');
        $this->addSql('CREATE TABLE store_order (/* ... */)');
        $this->addSql('CREATE TABLE store_inbox_message (/* ... */)');
        $this->addSql('CREATE TABLE store_outbox_message (/* ... */)');
        $this->addSql('CREATE TABLE store_trade_order_cancellation (/* ... */)');
    }
}

    步骤4：添加根Composer路径包¶

    将新应用程序添加为 Composer 路径包，以便整体应用程序可以加载它：

    // root composer.json
{
    "repositories": [
        {
            "type": "path",
            "url": "apps/{name}"
        }
    ],
    "require": {
        "crud-platform/{name}-app": "@dev"
    }
}

    运行： 

    composer update crud-platform/{name}-app

    步骤 5：更新根服务接线¶

    config/services.yaml¶

    添加应用程序源目录的排除项（它是通过自己的加载的） 作曲家包）：

    services:
    App\:
        resource: '../src/'
        exclude:
            # ... existing exclusions
            - '../src/{Name}/'  # Now lives in apps/{name}/

    config/routes.yaml¶

    如果应用程序具有先前通过 root routes.yaml 加载的路由， 为应用程序的路由添加导入：

    # config/routes.yaml
{name}_routes:
    resource:
        path: '../apps/{name}/config/routes.yaml'
    prefix: /api/v1

    config/packages/doctrine.yaml¶

    删除旧的实体映射并添加符号链接或引用映射：

    doctrine:
    orm:
        mappings:
            {Module}:
                dir: '%kernel.project_dir%/apps/{name}/src'
                prefix: 'App\{Module}'

    步骤 6：添加独立测试¶

    创建apps/{name}/tests/bootstrap.php：

    <?php

declare(strict_types=1);

use Symfony\Component\Dotenv\Dotenv;

require dirname(__DIR__) . '/vendor/autoload.php';

(new Dotenv())->bootEnv(dirname(__DIR__) . '/.env');

    将现有测试从根 tests/{Module}/ 移动到 apps/{name}/tests/：

    git mv tests/{Module}/ apps/{name}/tests/

    将测试命名空间更新为 App\{Module}\Tests\*。

    验证测试独立通过： 

    cd apps/{name}
php vendor/bin/phpunit

    步骤 7：更新 CI¶

    将新作业添加到 .github/workflows/ci.yml：

      test-{name}:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: php-actions/composer@v6
        with:
          php_version: "8.4"
          working_dir: apps/{name}
      - run: cd apps/{name} && vendor/bin/phpunit --coverage-clover ../../build/coverage/{name}.xml

    步骤 8：添加 Docker Compose 服务¶

    compose.yaml¶

      {name}-app:
    build:
      context: apps/{name}
      dockerfile: Dockerfile
    restart: unless-stopped
    environment:
      APP_ENV: ${APP_ENV:-prod}
      APP_DEBUG: "0"
      APP_SECRET: ${{NAME}_APP_SECRET:?required}
      DATABASE_URL: "mysql://${NAME}_MYSQL_USER:-app}:${NAME}_MYSQL_PASSWORD:-!ChangeMe!}@{name}-database:3306/${NAME}_MYSQL_DATABASE:-app}?serverVersion=8.0&charset=utf8mb4"
    volumes:
      - ./apps/{name}/var:/var/www/html/var
    depends_on:
      {name}-database:
        condition: service_healthy

  {name}-database:
    image: mysql:8.4
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${NAME}_MYSQL_ROOT_PASSWORD:-root}
      MYSQL_DATABASE: ${NAME}_MYSQL_DATABASE:-app}
      MYSQL_USER: ${NAME}_MYSQL_USER:-app}
      MYSQL_PASSWORD: ${NAME}_MYSQL_PASSWORD:-!ChangeMe!}
    volumes:
      - {name}-db-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

    compose.override.yaml（用于开发）¶

      {name}-app:
    environment:
      APP_ENV: dev
      APP_DEBUG: "1"
    volumes:
      - ./apps/{name}:/var/www/html  # Source mount for live reload
    ports:
      - "${NAME}_PORT:-8xxx}:80"

    步骤 9：验证清单¶

    按顺序运行这些检查。在考虑提取之前必须全部通过 完成。

    9.1 PHPUnit¶

    cd apps/{name}
php vendor/bin/phpunit
# All tests must pass

    9.2 容器 Lint¶

    cd apps/{name}
php bin/console lint:container
# Must compile without errors or deprecation warnings

    9.3 PHP斯坦¶

    cd apps/{name}
php vendor/bin/phpstan analyze
# Must pass at the app's configured level (target: Level 8)

    9.4 Deptrac（如果适用）¶

    # Ensure no new cross-module violations
composer deptrac

    9.5 Docker 构建¶

    docker compose build {name}-app
# Must build successfully

    9.6 迁移烟雾¶

    docker compose up -d {name}-database
docker compose run --rm {name}-app php bin/console doctrine:migrations:migrate --no-interaction
# Must complete without errors

    9.7 HTTP 烟雾¶

    docker compose up -d {name}-app
curl http://localhost:{PORT}/
# Should return a response (200 or 404, not connection refused)

    9.8 根测试套件¶

    php vendor/bin/phpunit
# Root test suite must still pass (service is loaded as path package)

    提取后：删除旧源¶

    全部验证通过且服务已在境内稳定运行 单一仓库：

    1. 从 src/{Module}/ 中删除遗留源（如果尚未通过 git mv 完成）
    2. 删除现在提取的表的旧根迁移（保留历史记录） 基线；新的迁移进入 apps/{name}/migrations/) 3.更新deptrac-baseline.yaml以删除遗留违规行为
    3. 网关路由准备就绪后，删除所有临时 Bridge/ 适配器

    在服务在生产环境中独立运行之前，不要删除遗留代码。 在过渡期间，整体架构仍然是生产主机。

    常见陷阱¶

    陷阱 症状 修复
    共享用户FK Doctrine\ORM\Mapping\MappingException 将 ManyToOne User 替换为 ownerUuid VARCHAR(36)
    缺少自动加载 Class not found 整体式 添加路径包到root composer.json
    命名空间不匹配 App\{Module}\* 与 App\{Module}\* 更新所有移动文件中的命名空间
    学说映射冲突 映射相同命名空间的两个 doctrine.yaml 文件 从根配置中删除旧映射
    测试数据库不匹配 SQLite 功能测试失败 使用VARCHAR代替ENUM，在SQLite上测试
    缺少环境变量 容器无法启动 使用 ${VAR:?required}
    端口冲突 bind: address already in use 在 compose.yaml 和 compose.override.yaml 中分配唯一的端口
    迁移基线缺失 Fresh DB 没有表 使用所有 CREATE TABLE DDL
    工作人员/调度程序取决于整体 工作孤立失败 确保工作人员传输配置在应用程序配置中是独立的
    硬编码整体路径 %kernel.project_dir%/var点错 在应用程序配置中使用应用程序相对路径
