    动态查询系统参考¶

    list()使用的基于表达式的动态查询引擎的完整参考 BaseServiceReadListTrait 和 RestController::requestProcess() 中的方法。

    1. @filter — 基于表达式的过滤¶

    1.1 概述¶

    GET /api/v1/manage/products?@filter=entity.price > 1000 && entity.enabled == true

    过滤表达式由ExpressionService::buildFilter()解析→ ExpressionDqlParser → ExpressionQueryBuilderAssembler，然后作为 DQL 注入 子查询：

    WHERE entity.id IN (
    SELECT filter_entity.id FROM Product filter_entity WHERE filter_entity.price > 1000
)

    如果 DQL 编译失败，系统将回退到内存中过滤（仅限管理； 非管理员获得AccessDeniedHttpException）。

    1.2 运算符¶

    操作员 意义 示例
    == 平等 entity.status == "active"
    != 不等于 entity.status != "deleted"
    > 大于 entity.price > 1000
    < 小于 entity.quantity < 10
    >= 大于或等于 entity.createdAt >= "2024-01-01"
    <= 小于或等于 entity.sortOrder <= 100
    &&、and 逻辑与 entity.enabled == true && entity.price > 10
    \|\|、or 逻辑或 entity.status == "active" \|\| entity.status == "draft"
    ! 逻辑非 !(entity.deletedAt == null)
    matches 正则表达式匹配 entity.name matches "/^A.*/"
    +、-、*、/ 算术 entity.price * entity.quantity > 10000
    in 列表中的值 entity.id in [1, 2, 3]
    not in 值不在列表中 entity.id not in [1, 2]
    ~ 包含（子字符串） entity.name ~ "hello"
    starts with 前缀匹配 entity.slug starts with "cat-"
    ends with 后缀匹配 entity.filename ends with ".jpg"
    <=>（宇宙飞船） 三路比较 对于排序表达式
    =、=== 严格平等 entity.id = 5

    1.3 链式属性（点路径遍历）¶

    使用点符号过滤关系：

    entity.category.name == "Electronics"
entity.tags.name in ["new", "sale"]
entity.parent.slug starts with "cat-"

    解析器自动为每个路径段生成 LEFT JOIN（例如，entity_category 表示 entity.category）。

    数学。*¶

    Math.abs(entity.value)
Math.sqrt(entity.area)
Math.ceil(entity.score)
Math.floor(entity.score)
Math.round(entity.price, 2)
Math.min(entity.x, entity.y)
Math.max(entity.x, entity.y)
Math.pow(entity.base, entity.exp)
Math.log(entity.val)
Math.log10(entity.val)
Math.sin(entity.angle)
Math.cos(entity.angle)
Math.tan(entity.angle)
Math.random(1, 100)
Math.pi()
Math.deg2rad(entity.degrees)
Math.rad2deg(entity.radians)
// and all other static methods on Math class

    ArrayCommon。*¶

    ArrayCommon.count(entity.tags) > 3
ArrayCommon.in_array("new", entity.tags.name)
// filter, map, reduce operate on PHP arrays (in-memory fallback only)

    过滤日期时间。*¶

    FilterDateTime.get("2024-01-01")  // creates DateTime in DQL
FilterDateTime.get("now", new \DateTimeZone("UTC"))

    1.5 NULL 处理¶

    entity.deletedAt == null      // IS NULL
entity.deletedAt != null      // IS NOT NULL
entity.deletedAt == true      // evaluates to false for NULL (SQL NULL semantics)

    1.6 DQL 验证¶

    解析后，ExpressionDqlParser::validateFragments($em)验证： - 所有字段引用都存在于实体的 Doctrine 元数据中 - 所有关系对于连接路径均有效 - 表达式中没有出现未知实体或字段

    1.7 内存回退¶

    当 DQL 编译失败时（例如，使用 ArrayCommon.filter 或复杂的表达式 Symfony ExpressionLanguage 功能），系统回退到： 1. 不过滤执行查询 2. 使用 LegacyEvaluator::evaluateBool() 过滤 PHP 中的结果，每个实体为 entity 变量 3. 如果 @sort 也存在，则使用 usort() 对结果进行排序

    此回退仅限于 ROLE_ADMIN，因为它将未过滤的数据加载到内存中。

    2. @sort — 内存排序¶

    GET /api/v1/manage/products?@sort=x.price > y.price

    强制内存模式。使用 x 和 y 作为两个实体来计算表达式 比较。将1或-1返回到usort()。 仅限管理员（由 assertPrivilegedQueryParameters()）。

    3. @order — DQL 排序¶

    GET /api/v1/manage/products?@order=price|ASC,createdAt|DESC,name|ASC

    语法：field|ASC 或 field|DESC，以逗号分隔用于多字段排序。

    多字段示例： 

    @order=category.sortOrder|ASC,entity.sortOrder|ASC,entity.name|ASC

    点路径自动转换为 LEFT JOIN 别名： 

    @order=category.name|ASC
→ LEFT JOIN entity.category entity_category
→ ORDER BY entity_category.name ASC

    4. @dql — 原始 DQL 子查询¶

    GET /api/v1/manage/products?@dql=SELECT p.id FROM App\Common\Entity\Product p WHERE p.price > 1000

    仅限管理员。原始 DQL 通过 $em->createQuery($subDql) 编译并注入为： 

    WHERE entity.id IN (SELECT p.id FROM ...)

    安全影响：允许跨数据库中的任何实体加入。始终受到限制 到ROLE_ADMIN。

    5. @select — DQL SELECT 投影¶

    GET /api/v1/manage/products?@select=entity.id, entity.name, entity.price, entity.category.name as categoryName

    返回部分数据而不是完整实体。安全限制：

    • 在 App\Identity\* 实体上被阻止 - 无法投影身份数据
    • 身份字段被阻止：user、profile、password、roles、email、phone、 phoneVerified、refreshToken、sessionKey、rawData

    当存在 @select 或 @groupBy 时，返回原始查询结果（不是 QueryBuilder）。

    6. @groupBy — DQL 分组依据¶

    GET /api/v1/manage/orders?@groupBy=entity.status&@select=entity.status, COUNT(entity.id) as total

    与 @select 一起使用进行聚合。点路径自动连接。

    7. @expands — 嵌套预加载¶

    GET /api/v1/manage/products?@expands=["entity.category", "entity.tags", "entity.category.parent"]

    语法：点路径的 JSON 数组。每条路径都会遍历 getter 并注入 __metadata：

    {
    "id": 1,
    "name": "Laptop",
    "category": {
        "id": 5,
        "__toString": "Electronics",
        "__metadata": { "id": 5, "name": "Electronics", /* full entity */ },
        "parent": {
            "id": 2,
            "__toString": "All Products",
            "__metadata": { /* full entity */ }
        }
    },
    "tags": [
        { "id": 10, "__toString": "new", "__metadata": { /* full entity */ } }
    ]
}

    __metadata 键包含完整规范化实体，而父键显示 简化形式。 FlatNormalizer 处理显示两者。

    8. @display — 响应整形¶

    GET /api/v1/manage/products?@display=complex（默认）

    价值 行为
    complex 按原样返回集合（序列化程序处理规范化）
    reduce 将每个实体映射到 {id, __toString} （最小表示）
    ["name", "price"] 通过 getter 提取命名字段
    {"name": "entity.getName()", "upper": "entity.name ~ 'Laptop'", "sqrt": "Math.sqrt(16)"} 评估每个实体的表达式；范围

    表达图示例： 

    @display={"name": "entity.name", "isExpensive": "entity.price > 1000", "priceFormatted": "Math.round(entity.price / 100, 2)"}

    9. @transform — 字段转换¶

    POST /api/v1/contents?@transform={"category": "Service.get({'name': ':value'}).getId()"}

    在创建/更新期间用于解析引用的实体。特征：

    • :value 占位符替换为该字段的原始请求值
    • Service.get($criteria)调用相关实体的服务来查找目标实体
    • Service.list($criteria) 返回身份包装数组
    • Service.get().getId() 返回解析的实体 ID（对于外键）
    • entity变量提供对当前实体的访问（带有.getId()的身份包装）
    • Math 和 ArrayCommon 在表达式范围内可用

    示例：使用类别名称而不是 ID 创建内容： 

    {
    "title": "My Article",
    "category": "Tutorials"
}
    @transform：{"category": "Service.get({'name': ':value'}).getId()} → 将“教程”解析为 ID 为 5 的类别实体 → 保存前设置content.category = 5

    10. @showDQL — 调试助手¶

    GET /api/v1/manage/products?@showDQL=true

    仅限开发（在非开发环境中抛出 AccessDeniedHttpException）。抛出一个 ValidatorException 包含完全编译的 DQL：

    DQL: SELECT entity FROM App\Common\Entity\Product entity WHERE entity.id IN(SELECT ...)

    11. @hints — 学说查询提示¶

    GET /api/v1/manage/products?@hints={"doctrine.readOnly": true, "doctrine.fetchAll": true}

    JSON 解码并通过 $query->setHint($key, $value) 应用。 仅限管理员。

    12. page & limit — 分页¶

    GET /api/v1/manage/products?page=2&limit=50

    参数 默认 描述
    page 1 页码（1-索引）
    limit 100 每页项目

    响应的分页器元数据：

    {
    "paginator": {
        "total": 250,
        "page": 2,
        "limit": 50,
        "pages": 5,
        "has_previous": true,
        "has_next": true
    }
}

    分页由RestController::pagination()应用。对于 QueryBuilder 输入，总计 通过DoctrinePaginator计算。对于数组，总计为 count()。

    13. 表达式缓存¶

    ExpressionService 使用 PSR-16 CacheInterface（可选）。当提供缓存时：

    • 缓存键：'expr_' . sha1($dataClass . '|' . $filter)
    • 存储值：{dql: compiledDQL, parameters: [{n: name, v: value}, ...]}
    • 缓存命中时：从缓存的 DQL 重新创建 Query，将参数包装在 Parameter 对象中

    缓存失效：只要实体类或过滤器表达式的 SHA1 密钥发生变化 变化。不需要显式的失效——新的过滤器生成新的密钥。

    14. 故障排除¶

    常见过滤器错误¶

    错误 原因 修复
    AccessDeniedHttpException: @filter expressions that require in-memory evaluation are restricted to administrators DQL 编译失败且用户不是管理员 简化表达式以仅使用与数据库兼容的运算符
    AccessDeniedHttpException: @dql is restricted to administrators 非管理员使用 @dql 删除 @dql 或使用管理员凭据
    AccessDeniedHttpException: @select cannot access identity data @select 定位身份字段或实体 从投影中删除身份字段
    ValidatorException: DQL: ... @showDQL 已设置 这是信息性的；删除 @showDQL 查看结果
    过滤器返回空结果 表达式太复杂或字段不存在 使用 @showDQL=true 检查编译的 DQL
    AccessDeniedHttpException: @sort is restricted to administrators 非管理员使用 @sort 使用 @order 代替数据库级别排序

    性能提示¶

    1. 使用@order而不是@sort：@order生成SQLORDER BY； @sort加载所有数据 进入记忆。
    2. 使用@expands进行预加载：渲染相关时防止N+1查询 实体。
    3. 使用 @select 进行视图投影：仅返回所需字段而不是完整字段 实体。
    4. 将 @filter 与 @select/@groupBy 组合：过滤器甚至会推送到数据库 与预测。
    5. 避免链式 @sort 表达式：每次比较都会计算 PHP 表达式。
    6. 表达式缓存：为ExpressionService提供PSR-16缓存以避免重新解析 相同的过滤器。
