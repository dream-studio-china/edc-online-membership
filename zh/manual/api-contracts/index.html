    API 合约¶

    REST API 表面的完整规范：请求/响应格式、身份验证、 URL 约定、分页、错误处理、文档和 Webhook 端点。

    1. 请求/响应信封¶

    1.1 成功信封¶

    所有成功的响应都使用以下结构：

    {
    "data": {},
    "code": 0,
    "message": "SUCCESS"
}

    使用分页（使用 page/limit 的 GET 请求）：

    {
    "data": [],
    "code": 0,
    "message": "SUCCESS",
    "paginator": {
        "total": 42,
        "page": 1,
        "limit": 100,
        "pages": 1,
        "has_previous": false,
        "has_next": false
    }
}
    领域 类型 描述
    data 混合 响应负载（对象、数组或 204 的空字符串）
    code 整数 始终0才能成功
    message 字符串 成功消息（默认"SUCCESS"）
    paginator 目的？ 仅适用于分页 GET 响应

    成功的 HTTP 状态代码： - 200 — 标准成功 - 201 — 创建（POST） - 204 — 已删除（无正文，Content-Type: application/json）

    1.2 误差包络¶

    {
    "code": 404,
    "message": "Entity is not found",
    "raw_data": ""
}
    领域 类型 描述
    code 整数 应用程序错误代码（通常是 HTTP 状态）
    message 字符串 翻译后的错误消息
    raw_data 混合 附加错误数据（调试）

    ExceptionInterceptor 为未处理的异常添加了一个 class 字段：

    {
    "code": 500,
    "message": "An error occurred",
    "class": "RuntimeException"
}

    1.3 使用的 HTTP 状态代码¶

    代码 意义 当
    200 200好的 总体成功；也用于应用程序级错误（检查 code 字段）
    201 201创建 成功创建 POST
    204 204没有内容 成功删除
    400 错误的请求 验证错误 (ValidatorException)、无效 JSON
    401 401未经授权 JWT 缺失或无效
    402 402需要付款 资金不足
    403 403禁止 访问被拒绝（非管理员访问管理端点）
    404 404未找到 未找到实体
    500 500内部服务器错误 未处理的异常

    2. 身份验证¶

    2.1 JWT 不记名令牌格式¶

    所有经过身份验证的请求包括：

    Authorization: Bearer <access_token>

    代币规格： - 算法：RS256（非对称，公钥/私钥对） - TTL：7200 秒（2 小时） - 有效负载：用户 ID、角色、过期时间、JTI（唯一令牌 ID）

    2.2 代币生命周期¶

    运营 端点 授权
    登录 POST /api/auth/login 无（公共）
    OTP 请求 POST /api/auth/otp/request 无（公共）
    一次性密码验证 POST /api/auth/otp/verify 无（公共）
    令牌刷新 POST /api/auth/token/refresh 无（公共；在正文中使用刷新令牌）
    令牌撤销 POST /api/auth/logout 已认证
    微信登录 POST /api/wechat/miniapp/login 无（公共）

    刷新令牌行为： - 不透明字符串，HMAC-SHA256 在数据库中散列 - 1 年生存时间 - 代币轮换：每次使用时更换 - 重用检测：如果提交了撤销/替换的刷新令牌，则所有用户令牌都将被删除 撤销

    智威汤逊黑名单： - 注销或令牌轮换时，访问令牌的 JTI 将添加到基于缓存的黑名单中 - TTL 与令牌的自然到期时间匹配（无永久存储） - 列入黑名单的 JTI 在身份验证步骤中被拒绝

    2.3 公共路由与经过身份验证的路由¶

    路线模式 访问
    /api/doc、/api/doc.json 公共访问
    /api/auth/* 公共访问
    /api/wechat/* PUBLIC_ACCESS（微信回调有签名验证）
    /api/v1/app/* IS_AUTHENTICATED_FULLY
    /api/v1/manage/* 角色管理员
    /api/v1/public/* 公共访问
    /api/payment/notify/* PUBLIC_ACCESS（支付提供商回调）

    3. URL 约定¶

    3.1 前缀¶

    所有 API 路由均以 /api/v1 为前缀。版本控制位于 URL 路径中。

    3.2 路径段¶

    /api/v1/{scope}/{resource}[/{id}][/{sub-resource}]
    范围 目的 示例
    manage 管理 CRUD 操作 /api/v1/manage/categories
    app 经过身份验证的用户操作 /api/v1/app/orders
    public 匿名只读访问 /api/v1/public/media

    特殊的非版本前缀： |前缀|目的| |--------|---------| | /api/auth |身份验证端点 | | /api/wechat |微信集成端点 | | /api/payment/notify |支付提供商 webhook | | /api/doc | NelmioApiDoc 文档 | | /system/entities |学说元数据内省 | | /system/router |路线列表 |

    3.3 RESTful 模式¶

    方法 网址 行动
    GET /api/v1/manage/{resource} 列表（分页）
    GET /api/v1/manage/{resource}/{id} 详细信息（单个实体）
    POST /api/v1/manage/{resource} 创建（单个或批量）
    PUT /api/v1/manage/{resource}/{id} 更新（单个）
    POST /api/v1/manage/{resource}/batch-update 批量更新插入
    DELETE /api/v1/manage/{resource}/{id} 删除

    ID 格式：接受整数 (\d+) 和 UUID ([0-9a-fA-F-]{36})。

    4. 分页¶

    4.1 参数¶

    参数 默认 描述
    page 1 页码（1-索引）
    limit 100 每页项目

    示例：GET /api/v1/manage/products?page=3&limit=25

    4.2 分页器响应结构¶

    {
    "paginator": {
        "total": 250,
        "page": 3,
        "limit": 25,
        "pages": 10,
        "has_previous": true,
        "has_next": true
    }
}
    领域 类型 描述
    total 整数 集合中的项目总数
    page 整数 当前页码
    limit 整数 每页项目
    pages 整数 总页数
    has_previous 布尔 true 如果页面 > 1
    has_next 布尔 true 如果页面 < 页

    对于非 GET 请求，分页器不存在。 RestController::pagination() 检查 $request->getMethod() !== 'GET'。

    5. 错误处理¶

    5.1 异常拦截器行为¶

    拦截 /api/* 路由上未处理的异常： 1. 记录异常（类、消息、跟踪） 2. 在 dev 中：让 Symfony 的默认错误页面处理它 3. 在生产中：返回具有适当 HTTP 状态的 JSON {code, message, class}

    5.2 具体异常处理¶

    例外 HTTP 状态 JSON code 灯塔
    ValidatorException 400 400 验证失败
    NotFoundHttpException 404 404 404 404未找到实体
    AccessDeniedHttpException 403 403 403 403权限被拒绝
    InsufficientFundsException 402 402 402 402钱包余额太低
    通用 \Exception 500 500 500 500意外错误

    5.3 添加自定义异常¶

    1. 在模块的 Exception/ 目录中扩展 \RuntimeException 2.从服务层抛出
    2. 捕获控制器并转换为warning()：
    catch (InsufficientFundsException $e) {
    return $this->warning($e->getMessage(), 402, '', 402);
}

    6. 数据格式¶

    6.1 JSON 请求/响应¶

    所有请求和响应都使用application/json。 RestController::success() 和 warning()方法调用$this->getSerializer()->serialize($response, 'json')。

    6.2 分段文件上传¶

    媒体上传端点使用multipart/form-data：

    POST /api/v1/app/media/upload
Content-Type: multipart/form-data

file: [binary]
storage: "local"
category: 3
alt: "My photo"
title: "Vacation 2024"

    6.3 数组与单对象输入¶

    创建端点接受两者： - 单个对象 {} → 创建一个实体，直接返回实体 - 数组 [{}, {}, {}] → 批量创建，包装在事务中，返回数组

    由FixJSON::getJSONType($content)检测到。

    6.4 @partial 批处理模式¶

    POST /api/v1/manage/products?@partial=true

    当@partial=true时： - 批量创建/更新跳过事务包装 - 失败的项目会被默默地跳过 - 成功的物品将被退回

    当@partial=false时（默认）： - 一次交易中的所有商品 - 任何失败都会回滚所有项目

    7. 翻译¶

    7.1 消息键约定¶

    错误消息使用人类可读的英语作为翻译键。 warning()方法 通过$this->getTranslator()->trans($error_msg)路由消息。

    7.2 区域设置协商¶

    kernel.request 上的 LocaleListener 以此优先级检测区域设置：

    1. ?_locale=zh-CN查询参数
    2. 具有质量权重的 Accept-Language 标头

    支持的区域设置：en、zh、zh_Hant、ja。不受支持的区域设置会回退到 en。

    8. 速率限制/CORS¶

    8.1 当前状态¶

    在框架级别没有实现系统范围的速率限制或 CORS 标头。 具体限制：

    资源 限制 实施
    OTP 请求 每部电话每 60 秒 1 次 应用级（Redis/缓存）
    一次性密码验证 每部电话 5 次尝试 应用级（Redis/缓存）

    8.2 未来计划¶

    计划在 API 网关层进行速率限制和 CORS 处理 微服务过渡。

    9. API 版本控制¶

    9.1 前缀策略¶

    所有版本化端点都使用 /api/v1 前缀。版本位于 URL 路径中，而不是 标头或内容协商。

    9.2 向后兼容规则¶

    改变 允许 需要
    添加新端点 是的 文档
    添加可选查询参数 是的 向后兼容
    添加字段到响应 是的 向后兼容
    更改响应中的字段类型 否 主要版本碰撞
    从响应中删除字段 否 弃用通知 + 主要版本更新
    更改回复信封格式 否 主要版本碰撞
    删除端点 否 弃用通知 + 主要版本更新
    更改身份验证要求 否 主要版本碰撞

    10.NelmioApiDoc¶

    10.1 #[OA]属性¶

    所有端点均通过 PHP 8 属性进行记录。查看 mixins 提供默认 OA 标准 CRUD 操作的属性：

    #[OA\Get(
    tags: ['List'],
    parameters: [
        new OA\Parameter(name: 'page', in: 'query', schema: new OA\Schema(type: 'string')),
        new OA\Parameter(name: 'limit', in: 'query', schema: new OA\Schema(type: 'string')),
        // ...
    ],
    responses: [
        new OA\Response(response: 200, description: 'Api list view'),
    ]
)]

    10.2 架构配置¶

    Schema 在 config/routes.yaml 中配置：

    app.swagger_ui:
    path: /api/doc
    controller: nelmio_api_doc.controller.swagger_ui

    JSON 架构可在 /api/doc.json 处获取。

    10.3 标签自动检测¶

    OpenApiEnricherListener 后处理 OpenAPI 输出： - 从operationId中提取资源名称（路由名称） - 显示标签的地图：产品、订单、类别、标签、内容、评论、页面、 媒体、设置、支付、钱包、系统、微信、商店、授权 - 删除通用操作类型标签（List、Detail、Create、Update、Delete、 Workflow) - 添加关键端点的摘要/描述

    10.4 记录新端点¶

    1. 在控制器动作上添加#[OA\*]属性 2.设置tags以匹配模块的标签名称
    2. 路由名称必须遵循{scope}-{resource}-{action}约定以进行自动检测：
    #[OA\Get(
    tags: ['MyModule'],
    parameters: [],
    responses: [new OA\Response(response: 200, description: '...')]
)]
#[Route('/custom-action', name: 'manage-myresource-custom-action', methods: ['GET'])]

    11. Webhook 端点¶

    11.1 通知模式¶

    支付网关和第三方服务回调公共 webhook 端点：

    POST /api/payment/notify/{payment}

    其中{payment}选择注册的支付网关（例如wechat，wallet， mock）。

    11.2 公共访问¶

    Webhook 端点是公共的（不需要 JWT）。身份验证是通过特定于提供商的 签名验证： - 网关验证回调签名/有效负载 - InvoiceService应用通知结果

    11.3 签名验证¶

    支付适配器使用 RsaClient 或特定于提供商的签名来验证 Webhook 处理前的真实性。无效签名会导致立即拒绝。
