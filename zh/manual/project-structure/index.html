    2. 命名约定¶

    命名空间¶

    图案 示例 笔记
    App\{Module}\* App\Trade\Trade\Service\OrderService apps/下的商业应用
    App\Core\* App\Core\Service\BaseService 框架共享库(packages/platform-kernel/)
    App\Bridge\* App\Bridge\PaymentWallet\WalletBalanceAdjustmentPort 临时整体适配器
    App\{Module}\Main\* App\Identity\Main\Entity\User 模块及子模块（主+微信、主+存储、交易+推广）
    App\{Module}\{Sub}\* App\Identity\Wechat\Entity\WechatUser 主模块下的子模块

    类命名¶

    类型 大会 示例
    实体 奇异 PascalCase，匹配表 Product、OrderItem
    存储库 {Entity}Repository ProductRepository
    服务 {Entity}Service ProductService
    服务接口 {Entity}ServiceInterface ProductServiceInterface
    控制器 {Entity}Controller ProductController
    消息处理程序 描述性后缀 TradeOrderCreatedHandler
    命令 帕斯卡命名法，{Verb}{Noun}Command PublishOutboxCommand
    例外 描述性后缀 InsufficientFundsException
    DTO 描述性后缀 CreateInvoiceRequest
    活动 {Entity}{Action}Event InvoicePaidEvent

    文件命名¶

    • 每个文件一个类。文件名与类名完全匹配。
    • .php 扩展名。
    • 接口文件使用与实现类相同的命名。

    表命名¶

    • snake_case，需要的模块前缀：trade_order，trade_product， store_membership、payment_invoice、wallet_transaction、common_category、 identity_refresh_token、inventory_reservation。
    • 去前缀的实体类名称可能与物理表名称不同（例如，PHP 类 Membership 映射到 store_membership 表）。

    3. 模块结构模式¶

    每个业务模块都遵循这样的目录布局：

    Controller/
  App/              # Authenticated user endpoints (ROLE_USER)
  Manage/           # Admin endpoints (ROLE_ADMIN)
  Public/           # Anonymous endpoints (optional, e.g., Common Media)
  Webhook/          # External webhook handlers (optional, e.g., Payment notify)
Entity/             # Doctrine entities (ORM attributes)
Repository/         # Doctrine repositories (extends ServiceEntityRepository)
Service/            # Business logic (extends BaseService)
  {Entity}ServiceInterface.php  # Interface for DI and testing
MessageHandler/     # Async message consumers
EventListener/      # Doctrine lifecycle or kernel event listeners
Command/            # CLI commands
Exception/          # Module-specific exceptions
DTO/                # Data transfer objects (immutable request/response shapes)
Event/              # Domain events (optional)
Security/           # Authenticators, resolvers (optional)
Resources/config/   # Module-specific services.yaml (optional)

    控制器从 App\Core\View 组成特征混合： 

    class ProductController extends RestController
{
    use ApiView;
    use ListApiViewMixin;
    use DetailApiViewMixin;
    use CreateApiViewMixin;
    use UpdateApiViewMixin;
    use DeleteApiViewMixin;

    protected array $requiredCreateProperties = ['name', 'price'];
    protected array $acceptedCreateProperties = ['name', 'price', 'description'];
    protected array $acceptedUpdateProperties = ['name', 'price', 'description'];
}

    4. apps/ 与 packages/ 的区别¶

    特色 apps/ packages/
    有自己的内核 是的 没有
    拥有自己的数据库 是的 没有
    有自己的迁移 是的 没有
    拥有自己的 Docker 镜像 是的 没有
    包含商业实体 是的 从不
    可独立部署 是（目标） 否（图书馆）
    拥有 composer.json 是的 是的

    5. 配置文件约定¶

    根整体 (config/)¶

    文件 目的
    services.yaml 服务接线、排除、_instanceof 自动标记规则
    routes.yaml 所有应用程序+身份验证+系统的基于前缀的路由导入
    packages/doctrine.yaml DBAL + ORM 配置，SQLite 测试后备
    packages/security.yaml 身份验证器、公共访问规则、角色层次结构
    packages/translation.yaml default_locale: en，翻译路径
    packages/workflow.yaml 顺序状态机（8 个状态 + 保护事件）
    packages/messenger.yaml 传输路由、异步/工作配置
    packages/nelmio_api_doc.yaml OpenAPI 3.1 架构、路径模式
    packages/framework.yaml 框架默认值、序列化器、验证

    每个应用程序配置 (apps/{name}/config/)¶

    每个应用程序都有自己的 services.yaml、routes.yaml、packages/doctrine.yaml 等。 这些是独立的，不引用根配置。学说映射点 仅限应用程序自己的实体。

    环境变量¶

    • 根整体：.env 位于存储库根目录
    • 每个应用程序：.env at apps/{name}/.env
    • Docker：compose.yaml环境部分中的默认值
    • 生产：.env.prod.local 来自 .env.prod.example

    6. 在哪里放置新代码¶

    您要添加的内容 它去哪儿了
    现有服务的新业务实体 apps/{service}/src/{Module}/Entity/
    现有实体的新 CRUD 控制器 apps/{service}/src/{Module}/Controller/{App\|Manage}/
    新的业务逻辑 apps/{service}/src/{Module}/Service/
    新的异步消息处理程序 apps/{service}/src/{Module}/MessageHandler/
    新 CLI 命令 apps/{service}/src/{Module}/Command/
    新的整合事件载体 packages/integration-contracts/src/
    新框架实用程序 packages/platform-kernel/src/
    新的临时桥/适配器 src/Bridge/（整体，将被删除）
    应用程序的新测试 apps/{service}/tests/
    新的跨领域集成测试 tests/Integration/
    应用程序的新迁移 apps/{service}/migrations/
    根整体表的迁移 migrations/

    经验法则：如果代码拥有业务状态，则它属于 apps/{service}/。 如果它是可重用的基础设施，那么它属于packages/。根 src/ 用于 仅过渡桥，将在网关切换后删除。
