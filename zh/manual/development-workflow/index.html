    开发工作流程¶

    1. 分支模型¶

    • main — 生产就绪代码。受保护的分支。可随时部署。
    • dev — 集成分支。功能分支首先合并到这里。
    • 功能分支 — feature/{description} 或 fix/{description}。已创建 来自 main （对于修补程序）或 dev （对于功能）。通过 PR 合并。
    • 发布分支 —（如果使用）release/{version}，从dev准备。

    工作流程¶

    git checkout dev
git pull origin dev
git checkout -b feature/my-feature
# ... develop, commit ...
git push origin feature/my-feature
# Create PR to dev on GitHub
# After review and CI green → merge to dev

    2. 编码标准¶

    PSR-12¶

    所有 PHP 代码都遵循 PSR-12。无定制 偏差。

    declare(strict_types=1)¶

    每个 PHP 文件必须以以下内容开头： 

    <?php

declare(strict_types=1);

    final 类¶

    在不是为继承而设计的类上使用 final。控制器， 命令、消息处理程序和实体类通常应为 final。 服务和接口不是最终的（以允许装饰和模拟）。

    类型声明¶

    • 所有方法参数和返回类型都必须显式键入 (PHP 8.4)。
    • 仅在不可避免时使用mixed（例如，通用BaseService::get()）。
    • 与仅 PHPDoc 类型相比，更喜欢联合类型。
    • 使用 PHPDoc @template TEntity 进行通用服务传播。

    PHP文档¶

    • 所有非私有方法都需要。
    • @param、@return、@throws 必须存在且准确。
    • 所有通用子类都需要 @extends / @implements（PHPStan Level 8）。

    3. 静态分析门¶

    PHPStan — 8 级¶

    # Run PHPStan
composer phpstan

# Configuration: phpstan.dist.neon
# Expected: zero errors in configured scope

    PHPStan 在 8 级 运行，错误容忍度为零。范围不包括： - 可选的 SDK 代码 (qiniu/php-sdk) - 异常类（可能有意扩展而不添加类型） - 记录的假阳性抑制

    Deptrac — 架构边界¶

    # Run Deptrac
composer deptrac

    强制执行： - App\Core\*不依赖任何业务模块 - 没有创建新的跨模块实体/存储库依赖项 - deptrac-baseline.yaml 记录准确的遗留源到目标债务

    Rector — 类型规则¶

    # Apply type improvements
composer rector:types

# CI dry-run check (must pass)
composer rector:types:check

    自动生成 Doctrine Collection/Repository PHPDoc 和其他类型 标准化。

    服务容器 Lint¶

    # Check container compiles without errors
composer lint:container

# Per-app:
cd apps/store && php bin/console lint:container

    4. 提交消息约定¶

    遵循Conventional Commits：

    <type>(<scope>): <description>

[optional body]

[optional footer]
    类型 用途
    feat 新功能
    fix 错误修复
    refactor 代码更改既不修复错误也不添加功能
    test 添加或更新测试
    docs 文档变更
    chore 构建、CI、依赖项、工具
    style 格式、空白
    perf 绩效提升
    范围 用途
    core packages/platform-kernel/ 更改
    common、identity、trade、store、inventory、payment、wallet 每项服务的更改
    ci GitHub Actions 工作流程
    docker Docker 配置更改
    integration 整合合同变更
    i18n 翻译更改

    示例¶

    feat(store): add StoreDirectoryOutboxListener for trade_store_directory projection
fix(payment): handle null payer in Invoice notification
test(trade): add OrderService pricing calculator integration tests
chore(ci): add per-app PHPUnit suite jobs
refactor(wallet): remove legacy user_id FK, use ownerUuid only

    5. 拉取请求清单¶

    在创建 PR 之前，请验证：

    • [ ] 所有测试均通过：composer test（root）+每个应用composer test
    • [ ] PHPStan 8 级：composer phpstan — 零错误
    • [ ] Deptrac 边界：composer deptrac — 没有新的违规行为
    • [ ] Rector 类型检查：composer rector:types:check — clean
    • [ ] 容器 lint（root + 受影响的应用程序）：composer lint:container
    • [ ] 新代码有测试（服务单元、控制器/端点集成）
    • [ ] 新实体具有匹配的存储库+迁移
    • [ ] 新集成事件在 packages/integration-contracts/ 中具有载体类别
    • [ ] API 更改反映在 #[OA\*] 属性中 (NelmioApiDoc)
    • [ ] 为任何新的面向用户的字符串添加翻译
    • [ ] 没有跨军种学说协会或 FK
    • [ ] 提交历史记录是干净的（在适当的情况下进行压缩）

    6. 代码审查期望¶

    审稿人检查：

    1. 正确性 — 代码是否按照其声称的那样执行？边缘情况是否得到处理？
    2. 架构合规性 - 层规则（控制器→服务→存储库）， 无跨服务 FK，用于跨服务状态更改的发件箱。
    3. 幂等性 — 集成事件使用者必须通过 eventId 实现幂等性。
    4. 事务边界 — 状态更改 + 发件箱写入同一数据库事务中。
    5. 安全性 — commonFilter() 范围界定、输入验证、代码中没有秘密。
    6. 测试覆盖率 — 新逻辑有测试。覆盖率必须保持≥ 90%。
    7. 静态分析 — 没有新的 PHPStan/Deptrac/Rector 违规行为。
    8. 代码风格 — PSR-12、strict_types、final（如果适用）。
    9. 命名 — 遵循约定（参见Project Structure）。
    10. 文档 — 更新了 API 文档属性，翻译了面向用户的字符串。

    7. CI 管道概述¶

    CI 管道通过 .github/workflows/ci.yml 在每个 PR 上运行：

    工作¶

    工作 命令 要求
    PHPUnit — 根集成 composer test 位于根目录 必须通过（963 项测试）
    PHPUnit — 常见 apps/common/ 中的 composer test 必须通过（74 项测试）
    PHPUnit — 身份 apps/identity/ 中的 composer test 必须通过（209 项测试）
    PHPUnit — 交易 apps/trade/ 中的 composer test 必须通过（412 项测试）
    PHPUnit — 钱包 apps/wallet/ 中的 composer test 必须通过（60 项测试）
    PHPUnit — 付款 apps/payment/ 中的 composer test 必须通过（37 项测试）
    PHPUnit — 商店 apps/store/ 中的 composer test 必须通过（20 项测试）
    PHPUnit — 库存 apps/inventory/ 中的 composer test 必须通过（11 项测试）
    覆盖范围合并 phpcov merge 覆盖所有套件 骨料≥90%
    PHPStan composer phpstan 零错误（8 级）
    德普特拉克 composer deptrac 没有新的违规行为
    校长类型 composer rector:types:check 清洁试运行
    容器棉绒 composer lint:container + 每个应用程序 必须编译

    环境¶

    • CI 在 PHP 8.4 上运行
    • 测试使用内存中的 SQLite (DATABASE_URL="sqlite:///var/test.db")
    • 测试作业不需要 Docker
    • 每个 PHPUnit 作业生成的覆盖工件，由 phpcov 合并

    覆盖门¶

    # Merge all coverage artifacts
phpcov merge build/coverage --clover build/coverage/merged.xml

# Check ≥ 90% threshold
# Current: 91.36% aggregate (1785 tests, 6098 assertions)

    8. 本地开发技巧¶

    本地运行静态分析¶

    # PHPStan
composer phpstan

# Deptrac
composer deptrac

# Rector (apply)
composer rector:types

# Rector (check only)
composer rector:types:check

# Container lint (root)
composer lint:container

# Container lint (all apps)
for app in common identity trade store inventory payment wallet; do
  cd apps/$app && php bin/console lint:container && cd ../..
done

    预提交检查¶

    在提交之前，运行完整的本地检查套件：

    # Root
composer phpstan && composer deptrac && composer rector:types:check && composer test && composer lint:container

# Each modified app
cd apps/store && composer phpstan && composer test && php bin/console lint:container

    IDE 配置¶

    • Psalm / PHPStan 插件：使用 phpstan.dist.neon 作为项目配置。
    • PHP CS Fixer：遵循 PSR-12。没有自定义规则集。
    • Doctrine：启用实体映射的 ORM 注释/属性支持。
