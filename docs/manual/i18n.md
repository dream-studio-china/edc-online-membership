# Internationalization (i18n)

## 1. Translation Architecture

The platform uses **Symfony Translation** component with 4 supported locales.
All user-facing messages — errors, success messages, entity/field names, enum
values, and JWT/WeChat error strings — pass through the translator.

| Locale | Language | File |
|--------|----------|------|
| `en` | English (default, identity mapping) | `translations/messages.en.yaml` |
| `zh` | Chinese (Simplified) | `translations/messages.zh.yaml` |
| `zh_Hant` | Chinese (Traditional) | `translations/messages.zh_Hant.yaml` |
| `ja` | Japanese | `translations/messages.ja.yaml` |

**~280 translation keys** per locale.

## 3. Adding New Translation Keys

### Step 1: Add to English File

Add the key to `translations/messages.en.yaml`. English keys usually mirror the
message value (identity mapping):

```yaml
# New key
"Order cannot be cancelled in current status": Order cannot be cancelled in current status
```

### Step 2: Add to Other Locales

Add translations to all other locale files:

```yaml
# messages.zh.yaml
"Order cannot be cancelled in current status": 当前状态的订单无法取消

# messages.zh_Hant.yaml
"Order cannot be cancelled in current status": 當前狀態的訂單無法取消

# messages.ja.yaml
"Order cannot be cancelled in current status": 現在のステータスでは注文をキャンセルできません
```

### Step 3: Use in Code

```php
// In a service (throw exception — translated by ExceptionInterceptor)
throw new \RuntimeException('Order cannot be cancelled in current status');

// In a controller (warning — translated by RestController)
return $this->warning('Order cannot be cancelled in current status');
```

### Step 4: Clear Translation Cache

```bash
php bin/console cache:clear
```

## 4. Translation Flow

All user-facing messages pass through the translator at specific integration
points:

### Exception Interceptor

`packages/platform-kernel/src/EventListener/ExceptionInterceptor.php`

Uncaught exceptions on API routes are caught and their messages are translated:

```php
final class ExceptionInterceptor
{
    public function __construct(
        private TranslatorInterface $translator,
    ) {}

    public function onKernelException(ExceptionEvent $event): void
    {
        $exception = $event->getThrowable();
        $translatedMessage = $this->translator->trans($exception->getMessage());

        $response = new JsonResponse([
            'code' => 500,
            'message' => $translatedMessage,
        ], 500);
        $event->setResponse($response);
    }
}
```

### Controller Warnings

`packages/platform-kernel/src/Controller/RestController.php`

Controller warning/error methods translate messages:

```php
class RestController
{
    #[Required]
    public function setTranslator(TranslatorInterface $translator): void
    {
        $this->translator = $translator;
    }

    protected function warning(string $message, int $code = 400, array $data = []): JsonResponse
    {
        return new JsonResponse([
            'code' => $code,
            'message' => $this->translator->trans($message),
            'data' => $data,
        ], $code);
    }
}
```

### Auth Errors

`apps/identity/src/Main/Controller/AuthController.php`

```php
class AuthController extends RestController
{
    private function error(string $message, int $code = 400): JsonResponse
    {
        return new JsonResponse([
            'code' => $code,
            'message' => $this->translator->trans($message),
        ], $code);
    }
}
```

### JWT Failures

`apps/identity/src/Main/Security/JwtAuthenticator.php`

```php
class JwtAuthenticator extends AbstractAuthenticator
{
    public function onAuthenticationFailure(Request $request, AuthenticationException $exception): ?Response
    {
        $messageKey = match ($exception->getMessageKey()) {
            'Expired JWT Token' => 'Token has expired.',
            default => 'Invalid credentials.',
        };

        return new JsonResponse([
            'code' => 401,
            'message' => $this->translator->trans($messageKey),
        ], 401);
    }
}
```

### Entity Field Names

`packages/platform-kernel/src/Controller/System/EntityController.php`

The system introspection endpoint translates field names:

```php
class EntityController
{
    #[Route('/system/entities/{entityName}', methods: ['GET'])]
    public function detail(string $entityName): JsonResponse
    {
```

## 5. Locale Detection

`packages/platform-kernel/src/EventListener/LocaleListener.php`

Registered at `kernel.request` priority 20. Detection priority:

### 1. `?_locale=` Query Parameter (Highest Priority)

```
GET /api/v1/app/products?_locale=ja
```

Explicit override. Takes precedence over everything else.

### 2. `Accept-Language` Header

Browser-sent header with quality factor ordering:

```
Accept-Language: ja-JP,ja;q=0.9,zh-CN;q=0.8,en-US;q=0.5
```

Mapping rules:
| Header Value | Locale |
|-------------|--------|
| `zh-CN`, `zh-Hans`, `zh` | `zh` |
| `zh-TW`, `zh-HK`, `zh-Hant` | `zh_Hant` |
| `ja-JP`, `ja` | `ja` |
| `en-US`, `en-GB`, `en` | `en` |

### 3. Configuration Fallback

`config/packages/translation.yaml`:

```yaml
framework:
    default_locale: en
    translator:
        default_path: '%kernel.project_dir%/translations'
        fallbacks:
            - en
```

If neither query param nor Accept-Language header matches, `en` is used.

### Sub-Requests

Sub-requests (ESI, fragments) are ignored by LocaleListener — they inherit
the master request locale.

## 6. Adding a New Locale

### Step 1: Create Translation File

```bash
# Example: Adding Korean
cp translations/messages.en.yaml translations/messages.ko.yaml
```

### Step 2: Translate All Keys

Translate all ~280 keys in the new file. Start by copying the English file
and replacing each value with the target language translation.

### Step 3: Add Locale Mapping (if needed)

If the new locale requires special `Accept-Language` header parsing, update
`LocaleListener.php`:

```php
// packages/platform-kernel/src/EventListener/LocaleListener.php
class LocaleListener
{
    private function detectLocale(Request $request): string
    {
        // 1. Query parameter
        if ($locale = $request->query->get('_locale')) {
            if (in_array($locale, ['en', 'zh', 'zh_Hant', 'ja', 'ko'])) {
                return $locale;
            }
        }

        // 2. Accept-Language header
        $lang = $request->getPreferredLanguage();
        return match (true) {
            str_starts_with($lang, 'ko') => 'ko',
            str_starts_with($lang, 'ja') => 'ja',
            str_starts_with($lang, 'zh') => match (true) {
                in_array($lang, ['zh-TW', 'zh-HK', 'zh-Hant']) => 'zh_Hant',
                default => 'zh',
            },
            default => 'en',
        };
    }
}
```

### Step 4: Add to Validated Locales

If there's a list of validated/supported locales, add the new locale:

```php
private const SUPPORTED_LOCALES = ['en', 'zh', 'zh_Hant', 'ja', 'ko'];
```

### Step 5: Add README Translation (Optional)

```bash
cp README.md README.ko.md
# Translate content
```

### Step 6: Clear Cache and Test

```bash
php bin/console cache:clear

# Test with query parameter
curl 'http://localhost:8080/api/v1/app/products?_locale=ko'
```

## 7. Translation Best Practices

1. **Use sentence case for messages** — "Order cannot be cancelled" not
   "ORDER_CANNOT_BE_CANCELLED".

2. **Include parameters in messages** — Use Symfony's `%param%` or `{param}`
   syntax:
   ```yaml
   "Property {property} is required": Property {property} is required
   ```
   ```php
   $this->translator->trans('Property {property} is required', ['{property}' => 'name']);
   ```

3. **Don't translate technical strings** — Error codes, log messages, and
   debug output should stay in English.

4. **Keep English keys simple** — The English key is usually the English
   message itself. Use quotes for keys with spaces or special characters.

5. **Run translation lint**:
   ```bash
   php bin/console lint:translations
   ```

6. **Extract missing keys**:
   ```bash
   php bin/console translation:extract --force en
   ```

7. **Always add all 4 locales** — When adding a new key, add it to all locale
   files in the same commit. Missing translations fall back to the English key.

8. **Test each locale** — Verify translations display correctly:
   ```bash
   curl -H 'Accept-Language: ja' http://localhost:8080/api/auth/login \
     -H 'Content-Type: application/json' \
     -d '{"username":"test","password":"wrong"}'
   # Error message should be in Japanese
   ```
